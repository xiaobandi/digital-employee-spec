# 六套件校验规范（test-suite-spec）

> 每个员工仓自带 `tests/run.py`（自包含运行器，零第三方依赖，只需 pyyaml），
> 六个套件全部**确定性执行，不需要 LLM / API Key**。
> 本规范定义每个套件校验什么、为什么这样设计。

## 运行方式

```bash
python3 tests/run.py                      # 全量
python3 tests/run.py --suite structure    # 单套件
python3 tests/run.py --filter wf-ecom-scout   # 按 slug 过滤
python3 tests/run.py --json reports/last.json # 落盘报告
```

退出码：0 全通过；1 有失败。落盘规则：`run.py` 默认**不写文件**（防止单套件
快照覆盖全量报告）；`reports/last-run.json` 只由平台级 `tools/run_all_tests.py` 写。

## 六套件

### 1. structure — 结构完备性

- 必需文件与目录存在（README / employee.yaml / persona / skills / workflows / tests…）
- 技能/工作流**目录名 == frontmatter `name`**
- README 相对链接逐条可达
- 全部 YAML 可解析

**为什么**：结构是所有校验的地基。链接可达是「文档可信」的最低标准——
死链比没有链接更伤信任。

### 2. contract — 契约闭环

- `employee.yaml` 清单与磁盘一致（声明了的技能必须存在，存在的必须声明）
- 工作流调用链可解析（引用的技能真实存在，含跨仓共享技能）
- `dependencies.yaml` 版本可解析、与 `agent-skills-core` 对得上
- **无重复物理存放**（共享技能在 core、私有技能在本仓，不得两处都有）

**为什么**：清单漂移是资产库腐烂的第一症状。声明与磁盘不一致时，
读文档的人永远不知道哪边是真的。

### 3. scenario — 多场景用例

- `tests/cases.yaml` 的每条用例含期望（expect），期望对应产出正文里
  **必须存在的可执行约束**（如「缺输入要停下来问」必须能在 SKILL.md 字面找到）
- 断言执行是字符串级的，**不需要开 LLM**

**为什么**：这是把「行为验收」压缩成「文本可验证」的关键设计。技能是
提示词即执行体——用例能否被满足，退化为正文有没有承载它的那条约束。
确定性的、可 CI 的，而且真能抓出退化的提示词。

### 4. script — 共享脚本回归

- 对每个带 `--selftest` 的脚本跑内嵌断言

**为什么**：共享脚本会物理复制到多个技能目录。自测与实现放同一份文件，
副本再漂移也会被当场发现（测试与实现同源，这是自测试（selftest）模式）。

### 5. doc — 文档命令可执行性

- 文档里写出来的命令照抄执行（路径可达 + cwd 明确）
- 例外：`docs/实测记录.md` 是**证据**不是操作手册，不参与复现校验

**为什么**：「文档里的命令跑不通」是开源项目最常见的信任杀手。
照抄必须能跑，写进规范就不能例外。

### 6. compliance — 纪律与合规

- 红线声明齐备（员工边界、技能禁止事项）
- 全仓扫描无 API Key（`sk-…`、`*_API_KEY=` 模式）
- 无真实 PII（手机号 / 邮箱等按模式扫描）
- 许可齐备
- 无本机绝对路径泄漏

## 平台级总回归（四层）

`tools/run_all_tests.py`（本库工程区，不入员工仓）叠加三层平台级验证：

| 层 | 内容 | 最近结果 |
|----|------|---------|
| 第一层 | 32 仓六套件全跑 | 7685/7685 |
| 第二层 | 规范合规 / 证据厚度 / 投产就绪三维审计 | 245/245 × 3 |
| 第三层 | 端到端：30 员工仓六套件真跑覆盖 | 30/30 |
| 第四层 | **行为级**：固定输入真跑 + 机器确定性复核 | 150/150 |

行为级验证独立于本文件，覆盖五类纪律：零编造、闸门、红线、数值纪律
（含 derived 申报：算术推导数字必须显式申报 `{"value": x, "calc": "算式"}`，
机器求值复核）、降级路径。任何一层失败即阻断发布。

## 用例编写约定

`tests/cases.yaml` 每条用例：

```yaml
- id: topic-mining-missing-input
  target: wf-indie-coldstart-topic-mining
  scenario: 缺少热帖来源时的行为
  expect:
    - 明确告诉用户缺什么，不要猜
    - 给出补齐材料的方式
```

期望必须是正文中**可字面找到**的约束；如果一条期望找不到承载文本，
要么补文档要么删用例——**不允许期望悬空**。
