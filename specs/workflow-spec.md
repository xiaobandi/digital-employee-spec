# 场景工作流规范（workflow-spec）

> 工作流 = `layer: L2-workflow`：把多个原子技能编排成端到端场景的复合单元。
> 与原子技能同规范（frontmatter + 正文段落），额外要求触发方式、调用链与失败处理。

## 1. 目录与命名

```
workflows/<wf-slug>/
├── SKILL.md            # 工作流定义（必需）
├── scripts/            # 编排脚本（可选）
├── docs/
│   ├── 使用示例.md      # 真实输入 → 真实输出
│   └── images/
│       ├── 00-effect.png       # 效果对比图（左输入 / 右产出，真实执行）
│       ├── 04-terminal-run.png # 终端回放
│       └── 08-demo-run.gif     # 真实执行录播（+ 同源 mp4）
└── （可选）out/         # 实跑产物
```

命名：`wf-<客群>-<能力>-<场景 slug>`（如 `wf-indie-coldstart-topic-mining`）。

## 2. frontmatter 必需字段

在原子技能 frontmatter 基础上：

```yaml
metadata:
  layer: L2-workflow
  owner: de_indie_coldstart_growth_officer
  phase: P0
  source: library          # library | repo
```

`description` 必须包含：**做什么 → 步骤链（→ 连接）→ 触发方式**，以及
「当用户要完成 XX、或触发了上述条件时使用」的触发声明。

## 3. 正文必需段落

| 段落 | 说明 |
|------|------|
| `# 标题` + 归属块 | 归属员工 / 触发 / 复杂度 / 阶段 |
| `## 一、这条工作流解决什么` | 步骤链一句话 + 业务收益（可算式） |
| `## 二、编排哪些技能` | 调用链：每个被调技能（含跨仓共享技能）及输入→输出 |
| `## 三、执行步骤` | 步骤明细：# / 步骤 / 技能 / 输入→输出 / **失败处理** |
| `## 四、输入输出` | 契约级输入规格与产出物 |
| `## 五、边界与合规` | 红线 + 人工确认环节 |

**失败处理是硬要求**：每个步骤必须写明上游产物缺失 / 空输入 / 校验不过时
的行为（中止并提示重跑上游 / 占位清单正常退出 / 人工介入）。禁止静默跳过。

## 4. 触发方式（三类）

| 类型 | 写法示例 | 说明 |
|------|---------|------|
| 定时 | 定时（每日 8:00） | 由承载平台的调度能力执行 |
| 人工 | 人工（提交 commit 摘要/日志） | 用户主动发起 |
| 事件 | 事件（主稿确认后） | 上游工作流完成 / 特定状态变更 |

同一员工的工作流可级联：WF1 定时产出 → WF2 事件触发消费 → WF3 汇总交付。
触发链必须在定义卡 F 段与 README 工作流表中一致呈现。

## 5. 调用链规则

1. **引用必须存在**：工作流声明的每个技能必须真实存在（本仓 `skills/` 或
   `dependencies.yaml` 声明的外部共享技能）——contract 套件强制校验。
2. **证据链不新增**：下游工作流的产出只能引用上游产物的证据；需要新证据
   就回退上游步骤，不得在下游「顺手编一条」。
3. **产物契约稳定**：上游落盘文件（如 `out/insight.json`）是下游的输入契约，
   改结构 = 破坏性变更，须升版本号并写 CHANGELOG。

## 6. 效果证据（发布硬标准）

- `00-effect.png`：左输入 / 右产出的真实对比图，**不得用环境探测截图充当效果**。
- `08-demo-run.gif/mp4`：真实执行录播，与 `reports/real-run/<slug>.md` 台账
  **同一次执行**；台账不存在则录屏不应存在（宁可响亮失败，不要安静缺图）。
- README 首屏内联 GIF；mp4 保留高清完整版（jsdelivr CDN 可加速外链）。
